# Benchmarks (plan section 17, phase P13)

56 programs in 8 families under `families/<family>/*.qasm`, plus an intentionally empty
`families/dynamarq/` (external programs, unavailable offline; no look-alikes were written, see its
README). Each family has a `meta.json` (why, main obligations, provenance, licence, notes; JSON
instead of the plan's `meta.yaml` to avoid a dependency).

| Family | Programs |
| --- | --- |
| teleportation | 6 (4 from P7 kept untouched, 2 generated) |
| active_reset | 4 |
| long_range_cnot (long-range CNOT / GHZ) | 8 |
| rus (repeat-until-success) | 8 |
| qec (repetition d=3,5 and surface d=3, 1/3/20/100 rounds) | 12 |
| magic_state (conditional S-like fix-up, `within`, `hard`) | 6 |
| lattice_surgery | 6 |
| artiq (synthetic ARTIQ-style kernels, NOT external code) | 6 |

Every program is written by the qtiming authors (Apache-2.0) and generated by
`python benchmarks/gen_families.py` (deterministic; `--check` compares with the files on disk).
They are toy circuits with the timing shape of each protocol, not validated physical protocols.

## Commands

    qtiming-bench run --suite benchmarks/families --contracts all --policies eq,sync,exp \
        --repeat 1 --out results/<run-id>/        # results.jsonl, manifest.json (+ .parquet if pyarrow)
    qtiming-bench check results/<run-id>/ --golden benchmarks/expected.json
    qtiming-bench truth --out benchmarks/families/       # ground_truth.json
    qtiming-bench diff --runs 200 --seed 1 --programs 3  # H1 differential
    qtiming-bench report results/<run-id>/ --tables results/<run-id>/tables/

`benchmarks/claims.json` maps each hypothesis to its command and says which are runnable now.

## Read this before trusting `expected.json`

`expected.json` is a REGRESSION SNAPSHOT of the checker as it was when it was generated: it records
what the current code answers, so a later change that flips a verdict is noticed. It is not
independent ground truth, and a cell being "as expected" says nothing about whether the verdict is
right. Independent evidence lives elsewhere: the reference executor, `tests/differential`,
`tests/property`, the H1 differential and `truth`. Regenerate with `qtiming-bench check
--update` only after reviewing every changed cell.

## What the cells show, and what they do not

* Only the IBM contract publishes gate durations (from an UNOFFICIAL snapshot), so on `artiq`, `q1`
  and `qua` every cell is `unsupported` (E-CT-MISSING) until durations are assumed, e.g.
  `--assume durations.x=32 --assume durations.h=32 ... --assume timeline.commit_lead=50`. The
  harness reports those cells; it does not skip them. The golden file covers the default run only.
* `while` loops (the `rus_while_*` programs) are `unsupported` on IBM (nested ifs and measurement
  in a branch are not allowed there). `timing.cap` exhaust labels are not implemented, so the
  exhaust handler is empty. The IBM-expressible form, `rus_unrolled_*`, is an approximation (see
  its notes in `meta.json`).
* The harness uses `--unroll-limit 16`, so the 20- and 100-round QEC programs are windowed (one
  iteration summarised, plan 9.7); only IBM qualifies, other contracts give `unsupported`
  (E-GRAPH-CUT). Programs annotated with a policy ignore `--policies` (an annotation wins).
* `ground_truth.json` (H2) holds exhaustive per-run executor violations only. The IBM executor
  emits none, so on the default contracts it is all `violated: false`: it does not yet show H2.
* `diff` covers executor-visible violations (O1, O2a, O5 drops). O3, O4 and O7 are covered by
  `tests/property/test_soundness.py`.
* Not done offline: Dynamarq programs, Parquet (needs pyarrow), figures (need matplotlib), the
  prereg tag, and the H3 full sweep and H6 hardware evidence.

## Known checker bug found by this suite

With assumed durations, `rus_while_cap*` / `rus_while_policy_*` on `qua` and `artiq` end in a bare
`AssertionError` (`assert merged is not None` in `graph/builder.py: arm`, reached from
`dispatch/qua.py` and `dispatch/artiq.py: if_`). Likely cause (not confirmed in the elaborator): a `while` whose body re-measures the bit
it tests unrolls to nested ifs on the same outcome proposition, so the else arm's label
contradicts the enclosing then arm. On Q1 the same programs are refused cleanly (E-ELAB-Q1-NOT-EQUALISABLE). The
harness reports these as `error` cells (default run: none, they are `unsupported` there).
